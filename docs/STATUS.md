## 1 Nov: student / teacher / admin workflow (v3)
- **Roles:** the CRCC role is removed everywhere (API, app, seeder, migration `c3d1f7a2e9b4`). Three roles remain: student, teacher, admin.
- **Sign-up:**
  - Admin sign-ups are active at once, and the new admin is signed straight in. The admins above that unit are notified. `ADMIN_SELF_SIGNUP=false` brings approval back.
  - Teacher sign-ups notify every admin who may approve them. Admins see a bell with an unread count and an approvals panel on the dashboard, and can approve or reject in one tap.
  - The teacher is notified when approved.
- **Register numbers:** every student has a permanent `STU-<year>-<seq>` register number, generated by the server. It is unique, backfilled for existing students, and shown in the roster, profiles and dashboards. The roster can be searched by it.
- **Teacher:**
  - New **Student activity** page: class KPIs, sessions per day, and a per-student table.
  - Each child profile ends with a full activity timeline: every session and slate check, answer by answer.
- **Admin:**
  - **Dashboard:** KPIs, pending approvals, a 14-day activity chart, level distribution, teacher activity and latest sessions.
  - **Students:** filter by school, class, grade or consent; search by register number; open a student's detail page to edit grade or consent, or to erase the student.
  - **Teachers:** classes, students, sessions and last login for each teacher.
  - Org admins see only their own part of the hierarchy.
- **Verified:** 130 backend + 67 frontend tests pass, plus a 22-step headless-Chrome workflow with no errors: sign-up → notification → approval → login, admin sign-up, and every dashboard on phone and desktop.

## 1 Nov audit and hardening (v2.2)
A second full audit (backend, frontend, database, login). Every fix below has a regression test or was verified in headless Chrome against the real stack.
- **Login:**
  - A new token issued right after a PIN change could be revoked instantly on Windows (same-millisecond timestamp). Fixed.
  - The lockout can no longer be used to lock a teacher out from another device.
  - Response timing no longer reveals which phone numbers are registered.
  - Malformed tokens return 401, not 500.
  - The login screen shows clear messages for "server unreachable", "wrong PIN" and the lockout.
- **Database:** `alembic upgrade head` failed on a fresh SQLite database (adding a foreign key needs batch mode). Fixed. A new test runs upgrade, check (no model drift), downgrade to base and upgrade again.
- **Sync / privacy:**
  - One bad file in a sync batch no longer blocks the phone's queue forever.
  - Voice answers without audio are never reported as accepted.
  - Erased children cannot be revived by stale offline edits.
  - Media from failed jobs is deleted.
  - Purged crops return 410, not 500.
  - Request, part and list sizes are capped, and ids must be UUIDs.
  - Timestamps are normalised to UTC.
- **Correctness/scale:**
  - Concurrent first `/today` or `/card` requests no longer cause a 500.
  - Learner updates take a per-child row lock.
  - Cards are generated only for active classrooms.
  - The CRCC summary and review queue now run a fixed number of queries.
  - Only the top-level admin may change the global bug library.
- **PWA:**
  - Sync no longer writes back an old token (which undid logout or a PIN change).
  - A roster edit made during an upload is no longer lost.
  - Answers saved after a session was auto-closed are uploaded.
  - The content pack updates without needing an upload.
  - Upload timeouts scale with batch size on 2G.
  - The mic is released if the kiosk closes during the permission prompt.
  - Service-worker updates wait until the kiosk is closed.
  - New: error boundary, role guard on `/crcc`, and leak-free media URLs.
  - Counting pictures render in rows of five again.

## 23 Oct audit and hardening (v2.1)
A full audit against GUIDE §6–13 found and fixed these issues. Each has a regression test.
- **Honesty:** misconceptions now need ≥2 *verified* reproductions. Tap guesses and un-probed errors can only reach "suspected". Action Cards separate confirmed from suspected counts, and the validator rejects un-hedged claims.
- **Privacy:**
  - CRCC users are blocked from classroom child data and can no longer change consent.
  - Full slate photos are deleted after cropping, and crops expire.
  - Erasure is now complete.
  - Every published CRCC cell holds at least 5 children.
  - Wrong PINs trigger a lockout.
- **Correctness:** re-confirming no longer double-counts evidence. Claude schema/auth failures fall back instead of returning a 500. Approved discovered bugs now enter the library. Tiny card groups merge correctly.
- **Teacher UX:**
  - The review queue is ranked and batched (5/day) with reasons and a skip option, and it says honestly when no recording exists.
  - Card groups show certainty chips.
  - The profile ladders scroll with visible edge fades.
  - The CRCC view says when small cells are hidden.
